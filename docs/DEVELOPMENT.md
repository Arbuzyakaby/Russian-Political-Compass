## Локальный запуск

Используйте Node.js 22 или новее; CI работает на Node.js 22. Для обычного запуска и модульных тестов зависимости не нужны.

```sh
npm run serve
```

Адрес — `http://localhost:4173`. Локальный сервер предназначен для разработки. Публичный сайт публикуется из `dist/` после проверок в GitHub Actions; `CNAME` хранит домен проекта. Исходники также можно разместить на обычном статическом хостинге.

## Архитектура

| Слой | Файлы и ответственность |
| --- | --- |
| Страница | `index.html`: каркас, диалоги, русские тексты до инициализации. |
| Оформление | `css/`: токены, темы, адаптивность и стили отдельных компонентов. |
| Данные | `js/data*.js`: версия, созывы, партии, люди, голосования, история выпусков. |
| Расчёты | `js/calc.js`, `js/quiz-calc.js`: функции без DOM. |
| Локализация | `js/i18n-*.js`: словари; `js/i18n.js`: выбор языка и подстановка строк. |
| Интерфейс | `js/compass.js`, `js/charts.js`, `js/quiz.js` и соседние модули. |
| Инициализация | `js/app.js`: связывает модули и запускает приложение. |
| Проверки | `tests/`: модульные проверки, браузерные сценарии и локальный сервер. |

Соблюдайте зависимости скриптов в HTML: расчётам нужны данные и утилиты, интерфейсу — расчёты и переводы. Не переносите вычисления в обработчики DOM, если их можно выразить чистой функцией.

Основные маршруты: `#/compass`, `#/quiz`, `#/votes`, `#/about`, главы книги `#/about/<глава>`, а также `#/duel/<a>-<b>[?c=<созыв>]`, `#/selfvote/<код>` и `#/srpc`; старые якоря `#ab-*` ведут на главы книги; старые `#/party/…` с 5.0 открывают компас с сообщением; результат открывается по `#/result/<код>`. Код ссылки содержит ответы и версию формата. Номер релиза и версия формата — разные сущности: выпуски 4.0 и 4.1 не меняют формат `3`.

## Проверки

```sh
npm test
```

Встроенный раннер Node проверяет расчёты, данные, ссылки на результаты, экспорт, локализацию и согласованность страницы. `tests/harness.js` загружает модули в `vm` с минимальными заглушками браузера. GitHub Actions запускает эти проверки при push и pull request.

Для браузерных проверок и подготовки оптимизированного пакета установите зависимости разработки:

```sh
npm install --package-lock=false
npx playwright install chromium webkit
npm run test:visual
```

Проверяются настольный Chromium и мобильные Chromium/WebKit, включая касания и экраны от 320 px. Эмуляция WebKit не заменяет проверку на физическом iPhone.

Ширина страницы при крупном тексте (4.4):

```sh
npm run check:fonts
```

`scripts/check-fonts.cjs` открывает четыре вкладки на двух языках при 320 px и `--text-k: 2` (текст 200%), подменяет шрифты темы на Verdana (самый широкий из обычных системных) и меряет ширину документа в Chromium и WebKit. Результат сравнивается с эталоном `docs/check-fonts-4.4.json`: рост ширины хоть в одной связке — ошибка; связка без записи в эталоне не должна быть шире 320 px. После осознанной правки вёрстки эталон перезаписывается `node scripts/check-fonts.cjs --write`. `PC_URL` — проверить уже запущенный сервер, `PC_ROOT` — папку (например, `dist`). Тест `tests/tools44.mobile.spec.js` делает ту же проверку на шрифтах темы в составе `npm run test:visual`.

Бюджет размера: `tests/budget.test.js` читает `dist/` и падает, если CSS первого экрана больше 300 КиБ, JS (оболочка и основной пакет) — 1000 КиБ (в 5.0 — 580 КБ: сборка пишет кириллицу как есть, `charset:"utf8"`), `index.html` — 125 КиБ; без `dist/` тест пропускается, поэтому `npm run prepare:release` в чек-листе стоит раньше `npm test`. `scripts/measure-startup.cjs <до> <после>` сравнивает две собранные папки: первый кадр и готовность приложения на 390 px при замедлении процессора ×4.

Конфигурация сама запускает сервер на порту 4173. Браузерные проверки исследуют поведение и геометрию, а не попиксельное совпадение с эталоном. При сбое смотрите HTML-отчёт, снимок экрана и трассу. Локальные отчёты, `node_modules` и lock-файл исключены из Git.

Перед изменением публичных текстов проверьте русский и английский варианты, мобильную ширину и отсутствие переполнения. Новые скриншоты README снимайте с локального сайта, используя демонстрационные ответы, и сохраняйте в `docs/images/`.

## Изменение интерфейса

- Добавляйте строки сразу на двух языках. Русский текст в HTML должен совпадать со словарём по соответствующему `data-i18n`.
- Темы задаются токенами. `data-theme` обозначает конкретную тему, `data-scheme` — светлый или тёмный режим.
- Сохраняйте управление с клавиатуры, видимый фокус, подписи элементов и поведение диалогов. Горячие клавиши страницы не должны вмешиваться в открытое модальное окно.
- Учитывайте отключённые анимации и `prefers-reduced-motion`.
- Проверяйте восстановление состояния из хранилища и переходы по hash-маршрутам без перезагрузки.

## Обновление данных

### Партии, люди и голосования

Партию добавляют в `js/data-parties.js`: стабильный `id`, русские тексты и `en`, реальные координаты и шесть под-осей, заявленная позиция с объяснением, текущие и исторические мандаты. Схема описана в начале файла; ориентируйтесь на актуальные соседние записи. Пересматривая оценку, приводите источники и аргументацию.

Политические деятели живут отдельно в `js/data-people.js`; не добавляйте их во фракционные расчёты. Голосования — в `js/data-votes.js`: уникальный `id`, дата, созыв, описание, позиции фракций и английский перевод. Соблюдайте хронологический порядок. Не подменяйте отсутствие подтверждённой позиции воздержанием.

### Новый созыв

1. В `js/data.js` найдите заготовку X созыва. Снимите `draft` только после подготовки проверенных данных, уточните годы.
2. У каждой партии сохраните прежнее `seats` в `seatsBy[9]`, затем запишите новые мандаты в `seats`. Различайте нулевой результат и отсутствие исторической записи.
3. Обновите `CURRENT_CONVOCATION`. Проверьте суммы мандатов и допущения существующих тестов.
4. При необходимости пересмотрите реальные и заявленные позиции с обоснованием. Согласуйте под-оси с координатами; исторические траектории не добавляйте.
5. Добавьте новые голосования с правильным `conv` и переводами.
6. Найдите описания диапазона созывов в HTML, метаданных, переводах и документации и обновите их по фактическому набору данных.
7. Запустите модульные и браузерные проверки; проверьте все созывы, графики и экспорт.

## Коммиты

Используйте заголовок `<тип>(<область>): <изменение>`; область можно опустить. Подходящие типы: `feat`, `fix`, `style`, `refactor`, `docs`, `test`, `chore`, `release`.

## Загрузка и мобильный интерфейс 3.2

Системные шрифты доступны сразу; дополнительные гарнитуры загружаются при выборе в настройках. Основные стили подключены синхронно, стили дополнительных разделов — через `media="print"` с переключением после загрузки и резервным `noscript`. Мобильные уточнения лежат в `css/mobile.css` после слоя анимаций; они сохраняются на сенсорных экранах до 1050 px при повороте устройства.

`welcome-boot.js` показывает приветствие после загрузки хранилища и переводов, не дожидаясь аналитики. Модуль `mobile.js` выбирает ближайшую точку при завершённом касании, отменяет выбор при движении/отмене жеста и увеличивает области попадания с учётом масштаба SVG.

Графики строятся через IntersectionObserver при приближении карточки к экрану. Наблюдается карточка с заголовком, а не пустой контейнер графика; для пустого графика резервируется высота. Ключ кэша учитывает данные, выбранную партию, язык, тему, шрифт, размер текста и ширину контейнера; ResizeObserver обновляет геометрию при повороте экрана. Без наблюдателей работает обычная отрисовка.

Тестовый сервер поддерживает gzip и опциональный HTTPS (`PC_TLS_CERT`, `PC_TLS_KEY`); `PC_ROOT` позволяет сравнить текущую версию с сохранённой ревизией в одинаковых условиях. Самоподписанные сертификаты предназначены только для локальных замеров и не добавляются в репозиторий.


### Пакет для GitHub Pages

`npm run prepare:release` объединяет и минифицирует стили и скрипты в `dist/` с помощью esbuild. Установите зависимости разработки через `npm install --package-lock=false`. Приветствие получает отдельный ранний пакет, остальное приложение — второй, который загружается после первого кадра интерфейса. Имена пакетов содержат хеш содержимого для обновления кэша. Изображения, manifest, robots и sitemap копируются в пакет; служебные отчёты и исходные документы туда не входят.

Обычный `npm run serve` открывает исходники, поэтому редактировать и запускать проект по-прежнему можно без сборки. GitHub Actions сначала проверяет модульные тесты, затем запускает браузерные сценарии на упакованной версии и только после успеха публикует тот же пакет через GitHub Pages.

### Техническое SEO

Основная индексируемая страница — русский HTML по `https://rupolitcompass.website/`. Параметр `?lang=en` переключает интерфейс; отдельного английского HTML в 4.x нет, поэтому отдельный hreflang не объявляется. Hash-маршруты не добавляются в sitemap как самостоятельные документы. Видимое описание проекта и методологии находится в исходном HTML и доступно без JavaScript. Обновляйте дату sitemap при содержательных изменениях и сохраняйте единственный canonical.

Браузерные проекты Chromium, mobile-chromium и mobile-webkit запускаются в CI параллельно на отдельных runners в официальном образе `mcr.microsoft.com/playwright:v1.63.0-noble` с готовыми браузерами и системными библиотеками. Версия образа согласована с Playwright в package.json. Публикация ждёт успешного завершения всех трёх.

## Палитра, копии, карта

Новые параметры живут в `pc-settings` и превращаются в data-атрибуты: camelCase-ключ `dotSize` становится `data-dot-size`. Резервная копия (`js/backup.js`) проверяет каждый ключ своей функцией; ключи удалённой «Моей партии» (`pc-my-parties`, `pc-party-draft`) перечислены в `PC.backup.RETIRED`: в новые копии они не попадают, а из старых пропускаются при восстановлении (`PC.backup.skipped(копия)`).

Метки Performance API `pc:markup`, `pc:styles`, `pc:data`, `pc:calc-ready`, `pc:first-draw`, `pc:export-ready` позволяют исследовать запуск в инструментах браузера.

## Плавность карты

Компас — SVG, приближение — смена `viewBox`; все изменения идут через одну функцию `render()` в `js/map-controls.js`. Кнопки «+»/«−», сброс и Ctrl+колесо не переключают вид, а подтягивают его к цели (каждый кадр проходится 22% оставшегося пути). Жесты (щипок, перетаскивание) применяются сразу, но не чаще раза за кадр; щипок держит под пальцами одну точку карты, после броска карта доезжает по инерции. Пока вид движется, у `#plot` есть класс `is-moving` (пульсация выбранной точки выключена). При отключённых анимациях (настройка или системное «уменьшить движение») вид меняется мгновенно. Щипок остаётся на событиях касаний: на масштабе 1 у карты `touch-action: pan-y`, двухпальцевый жест принадлежит браузеру, и отменить его можно только в `touchstart`.

## Соглашения по коду

- Комментарии — по-русски и про «почему», а не «что»: у каждой функции, чей смысл не очевиден, есть строка о том, зачем она нужна.
- Строка кода и CSS — не длиннее 160 знаков (тест в `tests/page.test.js`). Исключения: словари `js/i18n-*.js`, данные `js/data-*.js`, `js/quiz-data.js`, `js/party-templates.js` (там длинные тексты) и `css/tokens.css`.
- Одна инструкция на строку; тела функций и блоков — на отдельных строках.
- `!important` — только с комментарием, что именно перебивается. Единственный глобальный случай — пол кегля на телефоне в `css/mobile.css` (размеры `--fs-min-ui` и `--fs-min-body` заданы в `css/tokens.css`). С 4.3 в `css/app.css` и `css/party.css` не больше десяти строк с `!important` на файл (тест `tests/page.test.js`); остальное решено порядком и специфичностью (`:root`-префиксом у отдельного правила, а не у всего блока). Как проверялось снятие — см. [проверки 4.3](RELEASE_4_3.md).
- Значки интерфейса — только из спрайта Lucide (см. «Модули 4.3»): в разметке `<svg class="ico"><use href="#i-имя"/></svg>`, в скриптах `PC.icon("имя")`. Толщину линии задаёт `css/icons.css`, компонентные правила — только размер и цвет. Встроенные `url("data:image/svg…")` в CSS запрещены тестом, кроме шумовой текстуры фона в `css/base.css`.
- Окончания строк — LF во всех текстовых файлах (`.gitattributes`). Скрипты, которые правят файлы на Windows, должны писать с `newline=''` (Python) — иначе перевод строки записывается как CRLF.
- Кнопки не получают глобального минимума размера «весом»: общий минимум 44 px задан через `:where()` в `css/mobile.css`, и любой компонент перебивает его своим правилом без `!important`.
- Ключи словаря лежат в файле своей области: настройки, палитра, тур — `i18n-shell.js`, SRPC и пасхалки — `i18n-misc.js`, компас, карта, люди, экспорт — `i18n-compass.js`, результат теста — `i18n-quiz.js`. Тест следит, чтобы ключ не жил в двух файлах, а в английском не было кириллицы.

## Загрузка по требованию 4.4

Дуэль партий и «Голосую сам» не входят в основной пакет: их скрипты и `css/tools.css` загружает `PC.lazy` (`js/lazy.js`).

- **Перечень** лежит в `index.html`: `<script type="application/json" id="pcLazy">{"имя":{"js":"…","css":"…"}}</script>`. Это единственное место, где он записан; тег `<script src>` и `<link>` для таких файлов добавлять нельзя (тесты `page.test.js` и `tools44.test.js` следят за этим).
- **Сборка** (`scripts/prepare-release.cjs`) читает перечень, пишет каждый файл отдельным ресурсом с хешем (`js/duel.<хеш>.js`, `css/tools.<хеш>.css`) и подставляет эти имена в `#pcLazy` собранной страницы. Service worker кэширует их вместе с остальным пакетом.
- **`PC.lazy(name)`** возвращает промис и загружает модуль один раз; `PC.lazy.run(name, fn, кнопка)` — загрузить и вызвать `fn`, на время загрузки кнопка получает `aria-busy` и класс `lazy-busy`, ошибка — уведомление `lazy.fail`, следующее нажатие пробует снова. `PC.lazy.loaded(name)` — проверка загрузки.
- **Потребители** обращаются к модулям только через `PC.lazy.run`: кнопка дуэли на вкладке голосований и в карточке партии, ячейка матрицы, командная палитра, адрес `#/duel/<a>-<b>` (разбор — `routeDuel()` в `js/app.js`). «Голосую сам» подгружается `IntersectionObserver` за 400 px до блока (`PC.loadSelfVote()`).
- **Что должно остаться в основном пакете:** всё, что нужно до загрузки. Проверка формы ответов `pc-selfvote` — `PC.votes.validSelf` (её использует резервная копия), каркас блока «Проголосуйте сами» и кнопка дуэли — `css/votes.css`. Остальное в `css/tools.css` ждёт загрузки.
- **Тесты на исходниках** вызывают `PC.loadSelfVote()` и `PC.lazy("duel")` до обращения к модулям; `tests/harness.js` подключает `js/selfvote.js` и `js/duel.js` напрямую.
- **Адрес дуэли.** `js/nav.js` относит `#/duel/…` к вкладке голосований; `js/duel.js` пока окно открыто заменяет адрес (`history.replaceState`), а при закрытии возвращает прежний. Идентификаторы партий — латиница и цифры без дефиса (`u1`–`u6` — свои).

Проверки 4.4: `tests/shell.test.js`, `tests/budget.test.js`, `tests/loading.visual.spec.js` (Chromium), `tests/loading.mobile.spec.js` (ширина документа, Chromium и WebKit).
