# План развития проекта

Состояние на версию 1.4.0. Сделанное помечено `[x]`, оставшееся `[ ]` —
с пояснением, почему оно осталось.

## Контент/данные

- [x] **Версионирование экспертных оценок партий**: у партии есть поле `history` —
  структурированная траектория из точек «год + координаты + причина сдвига»,
  а не только текстовое описание в карточке. Точки видны слоем «Траектории»
  на компасе, полным списком в карточке партии и отдельным CSV в экспорте.
- [x] **Ключевые законопроекты и голосования**: отдельная вкладка `#/votes` —
  восемь знаковых законопроектов 2004–2022 годов (монетизация льгот, «закон
  Димы Яковлева», ратификация договора о Крыме, «суверенный интернет»,
  повышение пенсионного возраста, поправки к Конституции, признание ДНР и ЛНР,
  запрет «пропаганды» среди несовершеннолетних) с позицией каждой фракции,
  фильтром по темам и разбором «почему это голосование в списке». Под списком —
  матрица совпадения позиций между фракциями. Сводка по партии продублирована
  в её карточке.
- [ ] **Охват за пределами думских партий** — региональные партии и независимые
  кандидаты. Не сделано сознательно: по региональным партиям нет источника,
  сопоставимого по качеству с думскими программами и стенограммами, а достраивать
  координаты «на глаз» значит подорвать то единственное, чем проект ценен, —
  проверяемость обоснований. Возвращаться к пункту имеет смысл вместе с решением,
  откуда брать данные.

## Функциональность

- [x] **Диаграмма-паук / сравнение по под-осям**: каждая координата разложена
  на три более узкие шкалы (экономика — собственность, перераспределение,
  регулирование; государство — гражданские свободы, централизация,
  традиционализм). Радар живёт и в аналитике, и в результатах теста, накладывая
  профиль партии на профиль пользователя. Среднее трёх под-осей равно координате
  партии — это требование к данным, проверяется тестом.
- [x] **Прозрачность методики теста**: на экране результата раскрывается разбор —
  вклад каждого утверждения в свою ось, пятёрка сильнее всего повлиявших ответов,
  сумма вкладов и достижимый максимум. Формула показана целиком, а не только итог.
- [x] **Шаринг результата через URL**: маршрут `#/result/<код>`, где код — сорок
  символов, по одному на утверждение. Результат воспроизводится точь-в-точь
  вместе с разбором; ссылка никуда не отправляется, весь код лежит в адресе.
  Чужая ссылка собственные ответы не затирает.
- [x] **История прохождений** в localStorage: последние двенадцать результатов
  линией сдвига по обеим осям, с датами и возможностью открыть любое прошлое
  прохождение. Стирается отдельной кнопкой.

## Технически

- [x] **Visual/Playwright-тесты рендера**: `tests/visual.spec.js` — отрисовка
  компаса, отсутствие наложений подписей, 450 мест в парламентской диаграмме,
  прорисовка динамики и спектра, шесть лучей радара, прохождение теста до
  результата, ссылка на результат, переключение языка и тем. Playwright в
  зависимости проекта не входит (`npm i -D @playwright/test`), сервер для него —
  `tests/server.js` на `node:http`. Запуск: `npm run test:visual`.
- [ ] **Переход на ES-модули** вместо `window.PC`. Рассмотрено и отложено:
  `type="module"` заставляет отдавать файлы по HTTP (модули не работают с
  `file://`), то есть отнимает у проекта возможность просто открыть `index.html`.
  Коллизий имён при нынешнем размере нет — все модули пишут ровно по одному ключу
  в `PC`, и это проверяется тестом порядка подключения. Вернуться к пункту стоит,
  если модулей станет заметно больше или появится сборка по другой причине.
- [x] **`mobile-top.png` убран** из корня репозитория.
